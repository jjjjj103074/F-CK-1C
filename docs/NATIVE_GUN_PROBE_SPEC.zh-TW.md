# 原生機砲餘彈診斷包規格

使用者要求：直接提供測試包，使用 Steam 最新版 DCS 開啟一次任務，即可回傳能否讀取原生機砲彈量的證據。

1. 使用目前 MC／SM 工作內容建立獨立診斷快照。原本工作分支及未提交變更保留。
2. 由測試包檔案旗標啟用 DcsBridge 的 C++ 原生讀取；MC 使用現有 GunAmmunitionObservation，保持既有操作行為。
3. 每次飛行核對實際載入 CockpitBase.dll 的 PE 資訊及已知程式指紋。只有相符配置才呼叫 c_payload／gun 介面。
4. 原生讀取提供剩餘發數、有效性、版本與可判讀錯誤；有效零發與無法讀取分開記錄。來源每 0.1 秒觀察一次，保留正常 MC 32 Hz。
5. 記錄原生讀值與 MC 完成快照；來源未取得時維持無效，診斷模式由原生來源提供機砲資料。
6. 任務初始化與來源暫未建立時持續觀察；原生呼叫例外則記錄並停止該次飛行的原生呼叫。下一次飛行重新初始化。
7. 使用原生環境以外的記憶體／呼叫測試替身，驗證版本拒絕、物件鏈、有效零值、數量限制及呼叫失敗；Windows CI 建置完整 DLL 並執行專案驗證。
8. 完整測試包含可恢復的安裝、收集、還原入口與版本／DLL 雜湊。安裝保留既有模組；重複安裝相同包保留原始備份。
9. 使用預設按鍵，只需一次熱啟動任務、一次 Space 點射。回傳包含遊戲／模組記錄、MC CSV、來源版本。原生觀察全部失敗時，一併收集當次 CockpitBase.dll，供後續核對。
10. 結果明確區分建置／離線驗證與 DCS 實機結果。尚未由使用者執行前，標記 awaiting_user_capture。

互通來源及版本事實見 tools/native-gun-probe/REFERENCES.md。本輪依先前同意的 code-review、診斷分支提交／推送、Windows CI、取回產物順序交付測試包。
