# SM 整理規格

日期：2026-11-08～09。基準：本輪實作前工作目錄；獨立驗證副本快照 `c6701df3c60fd1bc3365561c50c0f887de72273c`。

## 已確認的要求

1. SM 作為唯一掛載與彈量權威。DCS 提供原始觀測；MC 的其他功能使用 SM 發布的資料。
2. 舊有初始飛彈數量、備用數量 API 與發射後估算扣量由掛點觀測取代。
3. SM 掌握全部固定掛點的配置、種類、數量、識別與觀測有效性，保留現有全用途掛載管理能力。
4. 掛點資料超過 0.5 秒沒有新有效批次時，保存最後內容並標記過期；新有效批次恢復觀測。
5. SM 管理武器掛點選擇與循環。進入／切換 DGFT 或 MSL 時，選第一個有效、有彈的空對空飛彈掛點；重按同模式，依固定掛點順序循環；NAV 清除邏輯選擇。
6. FCC 使用唯讀掛載資料，射擊／投放時序、許可與目標處理維持既有功能；武器操作經 SM 指令入口提交。
7. 選站要求與執行回覆各自保存，以編號與掛點核對；由明確選站要求統一 DCS 執行路徑。
8. 使用既有共用資料與 sigslot 同步通知，MC 組裝處持有連線；SM 內部實作可拆檔以提升易讀性。
9. 維持 MC 32 Hz、掛點 20 Hz、原生機砲 10 Hz。維持現有頂層元件與 DFLCC 分工。
10. 新增與修改的註解使用精簡功能描述，說明程式碼執行的工作。

## 選站的補充規則

- 同一個 MC 更新內連續重按同模式，依 FIFO 分別產生各次選站要求。
- 每次更新保留仍可用的要求；選中掛點耗盡後，以候選清單第一站接續。
- 重新掛彈或所選掛點的掛載身分改變時，重送明確選站要求。
- 有效空載的候選清單為空；觀測無效時保留最近要求，保存選擇意圖直到有效資料到達。
- acknowledged 保存轉接層最近完成的呼叫；pending 以要求與確認版本差異判斷。
- 空對空顯示數量同時提供完整性，供 HMCS 區分有效零枚與未知。

## 驗證範圍

- 逐掛點配置、未知型號與類型、數量及查詢完整性。
- 重複批次、0.5 秒邊界、過期、來源錯誤、恢復與重新掛彈。
- 進入、重選、切換、NAV、掛點耗盡與同次更新的多筆操作。
- 選站回覆的未到、錯站、過去／未來編號、正確回覆與更新通知。
- MC 更新順序、既有射擊／投放程序、Lua 動作映射、HMCS 數量有效性。
- 專案 C++ 排版、DCS ID 生成一致性及 Windows 完整建置／驗證。

架構來源與真機責任歸屬見 [SMS 研究](SMS_WEAPON_SELECTION_RESEARCH.zh-TW.md)。

## 單一指令入口（2026-11-09 確認）

使用者要求：「讓這個佇列管理 SM 的所有傳入指令，皆須通過它，作為解耦入口。」

- 全部模式選站、同模式循環、FCC 武器操作及取消要求由 StoresCommandQueue::submit 進入。
- SM 唯一消費入口；唯讀庫存查詢與來源觀測分別維持資料介面。
- 每筆指令取得 SM 指令編號；SM 依序將就緒要求交給外部動作佇列，並將指令編號映射到實際執行確認。
- 選站動作保留自己的掛點與要求版本；DCS 執行回覆完成該筆屏障後，才繼續後續動作。
- Exporter 僅發布視窗首項選站。CMS 核對全域動作序號與選站完成回覆，確保交錯更新仍依序執行。
- NAV／取消要求取消尚待執行的選站與啟動項目，保留停止項目；已送出動作的取消位置維持傳輸序號連續；尚在入口中的取消要求完成其 SM 回覆。
- MC 在指令路由前準備觀測，在各次模式／指令後派送就緒要求，並於 FCC 計時器後派送後續要求；模式選站先於新目標操作，主保險停止先於 CMS 中止。
- 既有至少 80 ms 的保持仍從實際動作執行確認後起算；選站確認與武器備便各自表達。

停止命令遇到未完成選站時，入口撤回前面的待選站與啟動項目，先排入取消及停止，
再依最新模式重新確認掛點。重新確認保留仍有效的選擇；停止命令的 SM 指令編號固定。
這項處理涵蓋一般 GunOff／PickleOff，以及主保險／NAV 取消，來源無效時仍可完成停止。

SM 指令編號與 DCS 傳輸序號各自維護；等待庫存的選站保留在 SM 入口，
其他 MC 功能可完成自己的控制操作及停止。火控以入口的確認查詢計算原有保持時間，
確認明細回收後，已完成的指令編號仍維持可查詢。
