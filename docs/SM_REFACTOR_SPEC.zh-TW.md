# 掛載管理規格

更新：2026-11-11。架構與來源依據見 [StoresManagement](../src/efm/F-CK-1C_EFM/Core/Systems/MissionComputer/Components/StoresManagement/README.md)，
原生介面契約見 [DCS API 指引](DCS_API_GUIDE.zh-TW.md)。

## 分工與資料

1. SM 作為 MC 的唯一掛載與彈量權威；DCS 提供原始觀測，其他元件使用唯讀 StoresData。
2. 九個固定掛點保存配置、數量、原始類型與識別、用途、掛載版本及最後有效觀測時間。
   空載、明確 CLEAN、已掛載零枚與未知分別表達；未知型號保留來源識別。
3. 數量由來源觀測更新，飛彈總數附完整性；機砲提供有效零發與來源有效性。
4. 新觀測批次更新內容與時間；重複批次沿用已接受內容。超過 0.5 秒標為 Stale 並保存最後讀值，新有效批次恢復。
5. MC 32 Hz、掛點 20 Hz、原生機砲 10 Hz。維持既有八個 MC 頂層元件與 DFLCC 分工。
6. 新增註解以精簡繁中說明程式功能；正式流程保留來源狀態與錯誤記錄。

## 選站與指令

1. 模式選站、同模式循環、FCC 武器操作及取消要求全部由 StoresCommandQueue::submit 進入，SM 為唯一消費者。
   每筆要求取得 SM 指令編號，並對應到外部動作的實際執行確認；已完成編號持續可查詢。
   佇列保存原始要求與回覆，以 take_next 交付要求、resolve 登記執行序號，並自行回收完成紀錄。
   SM 接受後保存模式意圖及待執行流程，處理停止、取消與重新選站規則。
2. 進入或切換 DGFT／MSL，選固定順序中第一個有效、有彈的空對空飛彈掛點；重按同模式輪換下一站。
   同次更新多筆操作依 FIFO 處理；週期更新保留仍可用的選擇，耗盡後改選候選首站。
3. 重新掛彈或所選掛點替換掛載時建立新要求。有效空載可選清單為空；來源無效時保留資料與選站意圖。
4. NAV 清除邏輯選擇；明確 NAV 操作遇到未完成要求時建立新的清空版本，相符 ACK 完成最新要求。
5. 每筆選站動作保存掛點與版本。Exporter 只發布執行視窗首項的選站；Lua 回覆呼叫完成後，CMS 核對動作序號、版本及掛點，接續後續操作。
6. SM 依 NAV／取消要求撤回待執行選站及武器啟動，保留停止。停止遇到等待選站時先撤回前綴、完成停止，再以最新模式重新確認掛點。
   已送出取消項維持傳輸序號連續；等待庫存的要求留在 SM，目標控制與反制操作仍可繼續。
   取消獨立記錄已取消的最高選站版本，結束該次 pending，保存要求內容與真正收到的 ACK。
   較晚抵達的真實 ACK 可更新完成紀錄；新選站使用較高版本並等待自己的回覆。
   主保險以 AbortWeaponUse 撤回先前武器啟動並安排必要停止；SM 接受後即處理撤回，後續新要求依序保留。
7. MC 組裝處持有同步通知連線；SM 完成資料寫入後發出變更事件。
   模式選站先於後續目標操作，主保險停止先於 CMS 中止，投放結束維持停止先於解鎖。
8. FCC 的 WeaponOperation 判斷使用資格，明確提出開始、正常結束與立即中止意圖。
   SM 的內部 WeaponExecution 管理執行確認、至少 80 ms 輸入保持及停止結果；正常保持從 MC 本次觀察開始 ACK 的時間起算。
   BeginWeaponUse 明確攜帶 LaunchPermission；投放超控決定由火控提供。
   EndWeaponUse 對應開始要求編號；AbortWeaponUse 撤回先前啟動並安排必要停止。
   SM 唯一寫入 StoresData.weapon_use；火控唯讀目前程序及最近拒絕的要求，較早回覆依要求編號核對。
   正常結束以停止已排入為準，FC 接續既有目標操作；取消保留取消結果及原有目標指定。
   開始要求在轉接層不可用時拒絕；已接受的程序與本次拒絕分別保存。
   取消後仍保存必要停止責任，正常放開與立即中止各自完成既有收尾。
   選站與開始 ACK 表示轉接層呼叫完成，武器離架及彈量由觀測更新。

## 原生機砲與安裝

1. 原生呼叫集中於 DcsBridge 私有 GunAmmunition 目錄；Core 接收型別化觀測。
2. 每次飛行核對 x64 PE、timestamp、image size、程式指紋與必要符號；配置採已實測的版本。
   檢查記憶體可讀性與函式可執行性，以 SEH 處理原生呼叫例外。
3. 等待 module／payload／mount 建立時持續取樣；呼叫失敗停止該飛行的原生呼叫，下一次飛行重新建立。
4. 正式彈量透過 MC 快照提供給 HMCS；測試專用的 SM CSV 通道與原始 Lua 記錄器已完成清理。
5. 安裝器與套件攜帶舊 Export 清理器，先備份並移除本模組舊區塊，保留其他匯出器原始位元組。
6. DCS ID 與參數由來源 JSON 及專案產生器維護。

## 驗收

- 逐站配置、分類、完整識別、數量、查詢完整性、重新掛彈與掛載替換。
- 新批次、重複批次、0.5 秒邊界、來源錯誤、過期與恢復。
- 進入、重選、切換、NAV、耗盡、同次多筆要求及錯誤／較早／正確 ACK。
- 單獨取消結束等待、有效／錯誤來源、延遲 ACK、取消後新要求與替代清空。
- 入口 FIFO、完成紀錄回收、停止優先、目標控制順序與既有操作保持時間。
- 原生版本拒絕、讀值限制、有效零發、失敗隔離、重設與 MC 傳遞。
- Lua 與 HMCS、安裝遷移、生成資料、排版、架構及指定 Windows 完整建置／分析／DLL 驗證。
- DCS 遊戲測試與自動測試結果分別記錄，見 [驗證報告](SM_REFACTOR_VALIDATION.zh-TW.md)。
