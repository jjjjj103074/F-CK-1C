## 後續重建原則

- [ ] 每次只加入一個可說明的飛控行為，先寫失敗測試，再加入最小實作。
- [ ] 子模組只接收自己需要的設定與輸入，不接收整份 FLCC 設定。
- [ ] 子模組自行提供指令綁定，Executive 只負責彙整與排定運算順序。
- [ ] `FlightControlComputer` 只負責 Pipeline 生命週期與輸入輸出轉接。
- [ ] 禁止加入舊新邏輯切換、靜默 fallback 或假成功輸出。
- [ ] 從確認輸入、輸出與責任邊界開始，重新建立 FLCC 測試。
