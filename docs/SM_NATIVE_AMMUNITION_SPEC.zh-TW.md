# SM 原生彈量與掛點狀態規格

本次規格來自 2026-11-02 的實機測試與本對話確認的修改方案。
Review 比較本輪修改前的工作目錄快照；原有未提交變更維持在快照內。

1. 固定九個掛點各自保存配置、身分、數量、有效性、最後有效觀測時間與掛載版本。
2. 配置區分 Unknown、Empty、Clean、Equipped；數量為零的已識別掛載保存其身分。
3. DCS Adapter 將空字串、原生類型與 `<CLEAN>` 轉成 Core 的配置；Core 保存原生不透明識別。
4. 機砲保存原生整數彈量、來源、更新時間及有效性；首次未知，原生零發有效。
5. 機砲數量使用已驗證的 Export `LoGetPayloadInfo().Cannon.shells`，移除固定 523 發及射擊時間估算。
6. Export 以裝置命令傳遞觀測給座艙，再透過具批次版本的座艙參數進入 DcsBridge。
7. 資料中斷時保留最近有效數字，並將目前有效性標記為未取得或過期；恢復時更新為新觀測。
8. SM 完成資料寫入後才發布掛點及機砲變更通知；相同內容的新樣本只更新來源時間。
9. 其他程式從 StoresData 或快照讀取庫存。FireControl 維持既有選站與武器使用程序。
10. HMCS 依機砲有效性顯示數字或 GUN ---；顯示選擇由 HMCS 負責。
11. 維持現有頂層元件；本次採用原生分類與識別，武器型號資料庫維持現有安排。
12. 提供 Export 安裝與移除入口，保存既有 Export 內容；正式模組安裝與打包包含 Export 程式。
13. Review 只比較本輪變更；來源保持未提交，驗證清楚區分自動測試、Windows 建置與 DCS 實機。

## 實測依據

- 任務 1：空，原生機砲 523→0。
- 任務 2：九站 CLEAN，原生機砲 523；九站 CLSID 均為 `<CLEAN>`。
- 任務 3：空、50% 初始機砲，原生 261→216；既有 MC 估算為 523→475.6。
- 空掛點的 CLSID 為空字串；原生掛點 table 是否存在與實體掛架狀態分別表達。
- 補彈尚未由使用者執行；自動測試以數量增加驗證接收與更新行為。

## 實作時序

MC 維持 32 Hz；座艙掛點維持 20 Hz；Export 機砲取樣 10 Hz，以 0.5 秒判斷過期。
機砲觀測走獨立資料型別與事件；既有空對空相容摘要與武器操作行為維持原有安排。
